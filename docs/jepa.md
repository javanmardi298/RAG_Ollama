## مرحلهٔ ۱ — ایدهٔ اصلی در سه جمله

1. **مدل‌های مولد** (GPT، MAE، مدل‌های diffusion) جزء‌به‌جزء ورودی را بازسازی/پیش‌بینی می‌کنند: توکن بعدی، پیکسل‌های پنهان، فریم بعدی.
   مشکل در دادهٔ پیوسته (تصویر/ویدیو/سنسور): بیشتر جزئیات **ذاتاً غیرقابل‌پیش‌بینی‌اند** (برگ‌های درخت، نویز). مدل ظرفیتش را صرف آن‌ها می‌کند.
2. **JEPA** (Joint-Embedding Predictive Architecture، پیشنهاد Yann LeCun در ۲۰۲۲): هر دو بخش ورودی را با encoder به embedding می‌بریم و
   **embedding بخش پنهان را از embedding بخش دیده‌شده پیش‌بینی می‌کنیم**. پس مدل فقط چیزی را یاد می‌گیرد که *قابل پیش‌بینی* است: ساختار، شیء، حرکت.
3. اگر به جای «بخش پنهان» بگذاریم «وضعیت بعدی جهان بعد از یک عمل»، همان معماری یک **world model** می‌شود:
   `z_next = predictor(z_now, action)` — و با آن می‌توان **قبل از انجام عمل، نتیجه‌اش را در ذهن شبیه‌سازی کرد** = برنامه‌ریزی و تصمیم‌گیری.

```
          context (دیده‌شده) ──► encoder ──► z_ctx ──┐
                                                       ├─► predictor ──► ẑ_target
     موقعیت هدف/عمل (mask token یا action) ───────────┘                      │
                                                                 loss = فاصله(ẑ_target , z_target)
          target (پنهان)    ──► encoder (یا EMA آن) ──► z_target ─────────────┘
```

**تله‌ی اصلی:** اگر encoder همه‌چیز را به یک نقطهٔ ثابت ببرد، پیش‌بینی بی‌نقص و loss صفر می‌شود ولی نمایش بی‌فایده است = **collapse**. کل تاریخچهٔ این خانواده، تاریخچهٔ جلوگیری از collapse است (مرحلهٔ ۴).

## مرحلهٔ ۲ — خانوادهٔ JEPA و «معادل‌ها» (به‌روز تا اکتبر ۲۰۲۶)

### خط زمانی JEPA

| سال | مدل | چه چیزی اضافه کرد | وضعیت |
|---|---|---|---|
| 2022 | [A Path Towards Autonomous Machine Intelligence](https://openreview.net/pdf?id=BZ5a1r-kVsf) | بیانیهٔ JEPA + world model + برنامه‌ریزی مبتنی بر انرژی | مقالهٔ موضعی |
| 2023 | [I-JEPA](https://arxiv.org/abs/2301.08243) | پیش‌بینی embedding بلوک‌های پنهان تصویر؛ EMA teacher؛ بدون data augmentation | تثبیت‌شده |
| 2024 | [V-JEPA](https://arxiv.org/abs/2404.08471) | همان ایده روی ویدیو (پیش‌بینی ویژگی‌های فضا-زمانی پنهان) | تثبیت‌شده |
| 2025 | [V-JEPA 2 / V-JEPA 2-AC](https://arxiv.org/abs/2506.09985) | بیش از ۱ میلیون ساعت ویدیو، encoder تا ~1B پارامتر؛ نسخهٔ action-conditioned با کمتر از ۶۲ ساعت دادهٔ ربات، برنامه‌ریزی zero-shot با CEM و انرژی L1 تا embedding تصویر هدف | تثبیت‌شده، کد و وزن باز |
| 2025 | [LLM-JEPA](https://arxiv.org/abs/2509.14252) | افزودن هدف JEPA به آموزش LLM (مثلاً دو «نما»ی یک چیز: متن ↔ کد) | پژوهشی (ICLR 2026) |
| 2025 | [LeJEPA](https://arxiv.org/abs/2511.08544) | اثبات اینکه توزیع بهینهٔ embedding گاوسی همسانگرد است + **SIGReg**؛ بدون stop-gradient، بدون teacher، یک ابرپارامتر | پژوهشی، بسیار اثرگذار |
| 2025 | [VL-JEPA](https://arxiv.org/abs/2512.10942) | بینایی-زبان: به جای تولید توکن، embedding متن را پیش‌بینی می‌کند؛ حدود 2.85 برابر عملیات decode کمتر | پژوهشی (ICLR 2026) |
| 2026 | V-JEPA 2.1 | ویژگی‌های متراکم (dense) بهتر برای segmentation/depth | جدید |
| 2026 | [LeWorldModel](https://arxiv.org/abs/2603.19312) | world model JEPA انتها-به-انتها از پیکسل با SIGReg؛ ~15M پارامتر؛ برنامه‌ریزی تا ~48 برابر سریع‌تر؛ تشخیص «غافلگیری» فیزیکی | پیش‌چاپ، امیدوارکننده |
| 2026 | پیش‌چاپ‌هایی مثل WA-JEPA (رانندگی)، D-JEPA (هم‌راستا با تصمیم)، VJEPA (variational) | کاربردهای تخصصی | هنوز تثبیت نشده — با احتیاط |

> «تثبیت‌شده» یعنی چند گروه مستقل نتیجه را تکرار کرده‌اند یا کد/وزن باز و استفادهٔ گسترده دارد. پیش‌چاپ‌های ۲۰۲۶ را تا تکرار مستقل «ایده» بدان، نه «استاندارد».

### معادل‌ها و رقبا — هر کدام چه چیزی را پیش‌بینی می‌کنند؟

| خانواده | نمونه‌ها | هدف آموزش | جلوگیری از collapse | خوب برای |
|---|---|---|---|---|
| Contrastive | SimCLR، MoCo، **CLIP** (تصویر↔متن) | نزدیک کردن جفت‌های مثبت، دور کردن منفی‌ها | نمونه‌های منفی | جست‌وجو و طبقه‌بندی zero-shot چندوجهی |
| Distillation / self-distillation | BYOL، **DINOv2 / DINOv3** | تطبیق خروجی student با teacher (EMA) | EMA + centering/sharpening | ویژگی‌های بصری همه‌منظوره (فعلاً قوی‌ترین backbone آماده) |
| Masked reconstruction (مولد) | **MAE**، BEiT | بازسازی پیکسل/توکن پنهان | لازم نیست (هدف پیکسلی است) | پیش‌آموزش ساده؛ ویژگی‌ها برای probe خطی ضعیف‌تر |
| Masked latent prediction | **I-JEPA، V-JEPA**، data2vec | پیش‌بینی embedding بخش پنهان | EMA teacher | ویژگی معنایی بدون augmentation دستی، ویدیو |
| Regularized (بدون teacher) | VICReg، Barlow Twins، **LeJEPA (SIGReg)** | پیش‌بینی/تطبیق + منظم‌ساز آماری روی embedding | واریانس/همبستگی یا گاوسی همسانگرد | ساده، پایدار، ابرپارامتر کم |
| World model مولد | **Dreamer V3**، Genie، **NVIDIA Cosmos**، مدل‌های ویدیوی مولد | پیش‌بینی آیندهٔ پیکسلی/توکنی | — | شبیه‌سازی، دادهٔ مصنوعی، بازی، رندر |
| World model نهفته (latent) | **TD-MPC2**، [DINO-WM](https://arxiv.org/abs/2411.04983)، **V-JEPA 2-AC**، LeWorldModel | پیش‌بینی آینده در فضای embedding (+ پاداش در TD-MPC2) | پاداش/encoder ثابت/SIGReg | کنترل و برنامه‌ریزی سریع، رباتیک |
| LLM به‌عنوان world model | پرسیدن «اگر X کنم چه می‌شود؟» از LLM؛ شبیه‌سازی کاربر (مثل مرحلهٔ ۶ همین پروژه) | پیش‌بینی توکن | — | دنیای متنی/نمادین، ابزارها، گفت‌وگو |

**جمع‌بندی کاربردی برای ۲۰۲۶:**
- ویژگی تصویری آماده می‌خواهی → **DINOv2/v3** یا **SigLIP/CLIP** (پختگی بیشتر). V-JEPA 2 برای **ویدیو و حرکت** بسیار خوب است.
- می‌خواهی عامل/ربات قبل از عمل «فکر کند» → **world model نهفته** (V-JEPA 2-AC، TD-MPC2، DINO-WM، LeWorldModel).
- دنیای مسئله متن و ابزار است (مثل پشتیبانی مشتری) → **LLM + ابزار + شبیه‌ساز کاربر**؛ JEPA اینجا فعلاً مزیت عملی روشنی ندارد (LLM-JEPA پژوهشی است).

### GEPA با JEPA فرق دارد (اشتباه رایج)
[GEPA](https://arxiv.org/abs/2507.19457) (Genetic-Pareto) یک روش **بهینه‌سازی prompt** است: LLM اجراهای ناموفق را می‌خواند، prompt را بازنویسی می‌کند و نامزدها روی جبههٔ پارتو نگه داشته می‌شوند (ICLR 2026). ربطی به JEPA ندارد ولی در این مخزن پیاده شده: `src/labkit/optimize.py` (با جریمهٔ طول و انتخاب روی validation، چون گزارش شده prompt از 2.4k به 8.8k کاراکتر رشد کرده و دقت تست افت کرده است — overfitting).

## مرحلهٔ ۳ — I-JEPA کوچک (دست‌به‌کار)

```bash
python scripts/jepa1_ijepa_digits.py            # دو seed، حدود ۴ دقیقه
python scripts/jepa1_ijepa_digits.py --epochs 80 --seeds 1 2 3   # نتیجهٔ مطمئن‌تر
```

**چه اتفاقی می‌افتد** (`src/jepa_lab/ssl.py`):
1. هر رقم ۸×۸ به شبکهٔ ۴×۴ از patch های ۲×۲ تقسیم می‌شود (۱۶ «توکن»).
2. یک بلوک ۲×۲ از patch ها (۴ از ۱۶) پنهان می‌شود → `sample_masks`.
3. encoder (Transformer کوچک) فقط patch های دیده‌شده را می‌بیند (attention mask).
4. predictor در جای patch های پنهان `mask_token` می‌گذارد و embedding آن‌ها را حدس می‌زند.
5. هدف: embedding همان patch ها از دید **کامل** تصویر؛ چهار نسخه:
   - `ema`: هدف از کپی EMA encoder بدون گرادیان (I-JEPA)
   - `sigreg`: هدف از خود encoder + SIGReg (LeJEPA) — `loss = (1-w)·pred + w·SIGReg`
   - `naive`: بدون هیچ درمانی (برای دیدن collapse)
   - `pixel`: پیش‌بینی پیکسل‌ها (شبیه MAE)
6. ارزیابی استاندارد SSL: encoder را **منجمد** کن، میانگین embedding ها را بگیر، یک **linear probe** (رگرسیون لجستیک) برای کلاس رقم آموزش بده.

**نتیجهٔ واقعی روی همین لپ‌تاپ (CPU، ۴۰ epoch)** — فایل `results/jepa1_ijepa_digits.json`:

| روش | میانگین دقت probe | کمینه | بیشینه |
|---|---|---|---|
| پیکسل خام (baseline) | 0.968 | 0.964 | 0.971 |
| pixel (MAE-like) | 0.890 | 0.882 | 0.898 |
| ema (I-JEPA) | 0.820 | 0.813 | 0.827 |
| sigreg (LeJEPA) | 0.810 | 0.693 | 0.927 |
| encoder تصادفی (baseline) | 0.807 | 0.784 | 0.829 |

(seeds [7, 8]، 40 epoch؛ sigreg در یک seed 0.927 و در دیگری 0.693 — **ناپایداری بالا**، خودش یک درس است.)

**تفسیر صادقانه (مهم‌ترین درس این مرحله):**
- پیکسل خام برنده است چون ارقام ۸×۸ از قبل تقریباً خطی‌جداپذیرند و ۱٬۳۰۰ تصویر برای یادگیری بازنمایی کم است.
- معیار درست در این مقیاس: (الف) فاصله از **encoder تصادفی** (همان معماری بدون آموزش)، (ب) رتبه بین روش‌های یادگرفته.
- نتایج بین seed ها نوسان دارد → همیشه چند seed اجرا کن و بازه گزارش بده، نه یک عدد.
- مزیت JEPA در **دادهٔ بزرگ و پرجزئیات** (تصویر واقعی، ویدیو) و در **world model** (مرحلهٔ ۵) ظاهر می‌شود؛ ادعای «JEPA همیشه بهتر است» درست نیست.

تمرین: `--epochs 100`، `dim=128` را امتحان کن؛ `sigreg_weight` را 0.2/0.5/0.8 کن (در کد `train(..., sigreg_weight=)`)؛ اندازهٔ بلوک ماسک را در `sample_masks(block=3)` بزرگ کن.

## مرحلهٔ ۴ — collapse و سه درمان

```bash
python scripts/jepa2_collapse.py
```

برای هر نسخه سه عدد را دنبال کن (`src/jepa_lab/sigreg.py → collapse_stats`):
- `loss` — **گمراه‌کننده**: در collapse به صفر می‌رسد.
- `mean_std` — پراکندگی embedding ها بین تصاویر مختلف؛ نزدیک صفر = همه‌چیز یک نقطه.
- `effective_rank` — چند بُعد واقعاً استفاده می‌شود (از ۶۴).

| نسخه | loss | mean_std | effective_rank (از ۶۴) | probe |
|---|---|---|---|---|
| naive | 0.0001 | 0.0038 | 15.2 | 0.860 |
| ema | 0.0059 | 0.0296 | 10.4 | 0.813 |
| sigreg | 0.0445 | 0.0701 | 21.8 | 0.927 |

naive: کمترین loss و کمترین پراکندگی = collapse؛ با این حال probe آن هنوز 0.86 است چون StandardScaler تفاوت‌های ریز را بزرگ می‌کند (نکتهٔ پایین را ببین).

درمان‌ها:
| درمان | ایده | هزینه |
|---|---|---|
| نمونهٔ منفی (contrastive) | جفت‌های نامرتبط را دور کن | batch بزرگ، انتخاب منفی‌ها |
| EMA teacher + stop-gradient (BYOL، I-JEPA، DINO) | هدف از کپی کندِ encoder می‌آید و گرادیان نمی‌گیرد | ابرپارامترهای حساس (momentum، schedule)، توجیه نظری ضعیف |
| منظم‌ساز آماری (VICReg، **SIGReg**) | توزیع embedding ها را مستقیماً کنترل کن | یک وزن؛ SIGReg در اندازهٔ batch و بُعد خطی است |

**SIGReg در ۵ خط** (`sigreg.py`): embedding ها را روی چند جهت تصادفی project کن؛ برای هر projection تابع مشخصهٔ تجربی (`mean(cos(tx))`, `mean(sin(tx))`) را با تابع مشخصهٔ N(0,1) یعنی `exp(-t²/2)` مقایسه کن (آزمون Epps–Pulley)؛ میانگین خطا = جریمه.
اگر همهٔ projection های یک‌بعدی گاوسی استاندارد باشند، توزیع چندبعدی به گاوسی همسانگرد نزدیک است (ایدهٔ Cramér–Wold) → هیچ بُعدی نمی‌میرد.

> نکتهٔ ظریف: linear probe با `StandardScaler` ممکن است collapse را پنهان کند (تفاوت‌های بسیار کوچک را دوباره بزرگ می‌کند). همیشه خود پراکندگی را هم گزارش کن.

## مرحلهٔ ۵ — world model و تصمیم‌گیری با برنامه‌ریزی

```bash
python scripts/jepa3_world_model_planning.py
```

**دنیا** (`world_model.py → DotWorld`): یک نقطه در مربع واحد که فقط به صورت تصویر ۱۲×۱۲ دیده می‌شود. عمل = جابه‌جایی (dx, dy) حداکثر 0.1. دیوارها برش می‌دهند.

**آموزش — بدون پاداش، بدون برچسب** (مثل V-JEPA 2-AC و LeWorldModel):
```
z   = encoder(تصویر_t)          z' = encoder(تصویر_t+1)
ẑ'  = z + predictor(z, action)   (residual: فقط «تغییر» را پیش‌بینی کن)
loss = ||ẑ' - z'||²  +  w · SIGReg([z, z'])
```
داده فقط تعامل تصادفی است (۶٬۰۰۰ گذار). مدل هرگز «هدف» یا «پاداش» نمی‌بیند.

**تصمیم‌گیری = MPC با روش Cross-Entropy (CEM)** (`cem_plan`):
1. تصویر هدف را encode کن → `z_goal`.
2. ۲۵۶ دنبالهٔ عمل تصادفی (افق ۶ گام) نمونه بگیر.
3. هر دنباله را **در فضای نهفته** با predictor جلو ببر (بدون اجرای واقعی).
4. «انرژی» = فاصلهٔ L1 تا `z_goal` (همان معیار V-JEPA 2-AC). ۳۲ دنبالهٔ بهتر (elite) را نگه دار، میانگین/انحراف را به‌روز کن، ۴ بار تکرار.
5. **فقط اولین عمل** را اجرا کن، مشاهدهٔ جدید بگیر، دوباره برنامه بریز (receding horizon).

| مدل | planner | نرخ موفقیت | میانگین فاصلهٔ نهایی | گام تا هدف |
|---|---|---|---|---|
| با SIGReg | cem | 1.00 | 0.063 | 10.233333333333333 |
| با SIGReg | random | 0.10 | 0.456 | 11.333333333333334 |
| با SIGReg | oracle | 1.00 | 0.026 | 3.2333333333333334 |
| بدون SIGReg | cem | 0.13 | 0.586 | 1.75 |

R² موقعیت از z: با SIGReg 0.999، بدون SIGReg 0.244. loss نهایی بدون SIGReg: 7.0e-07 (collapse).

**درس‌ها:**
- planner هیچ پاداشی ندیده؛ فقط embedding پیش‌بینی‌شده را با embedding تصویر هدف مقایسه می‌کند → «هدف را با تصویر بده» (goal-conditioned).
- `position_probe_r2` نزدیک ۱ یعنی موقعیت واقعی (x,y) به‌صورت خطی در z هست، با اینکه هیچ‌وقت به مدل داده نشده.
- `effective_rank` حدود ۲ تا ۳ از ۱۶: دنیا واقعاً دوبعدی است و مدل همین را کشف کرده — نشانهٔ خوب، نه collapse (collapse یعنی `mean_std`≈0 و loss≈0).
- بدون SIGReg: loss عملاً صفر، z ثابت، برنامه‌ریزی در حد تصادفی. **همان collapse مرحلهٔ ۴، این بار با هزینهٔ تصمیم‌گیری.**
- CEM از oracle کندتر به هدف می‌رسد (گام‌های بیشتر): هزینهٔ عدم قطعیت مدل. تمرین: `horizon`، `samples`، `iters` را تغییر بده و زمان/موفقیت را بسنج.

## مرحلهٔ ۶ — «غافلگیری» برای کشف ناهنجاری و ایمنی

```bash
python scripts/jepa4_surprise.py
python scripts/jepa4_surprise.py --noise 0.05      # دوربین نویزی: مقاومت سیگنال
```
خطای پیش‌بینی world model = **surprise**. حرکت عادی قابل‌پیش‌بینی است؛ «پرش» (teleport، از نظر فیزیکی ناممکن) نیست.

نتیجه: ROC AUC = 1.000؛ میانگین خطای حرکت عادی 0.0089 در برابر 32.80 برای teleport (189 مورد از 2000).

این همان ایدهٔ «violation of expectation» است که V-JEPA و LeWorldModel برای فهم شهودی فیزیک نشان داده‌اند.
در صنعت: هشدار وقتی یک فرایند **اثر همیشگی‌اش را نداشت** (شیر باز شد ولی فشار تغییر نکرد)، ربات لیز خورد، سنسور مقدار ناممکن داد، تراکنش با الگوی همیشگی کاربر نمی‌خواند.
آستانهٔ هشدار را مثل مرحلهٔ ۴ پروژهٔ اصلی روی validation و با نرخ هشدار کاذب قابل‌تحمل انتخاب کن.

## مرحلهٔ ۸ — کجا برای تصمیم‌گیری به کار می‌روند؟ (و کجا نه)

| حوزه | تصمیم | نقش JEPA / world model | وضعیت ۲۰۲۶ |
|---|---|---|---|
| رباتیک (گرفتن و جابه‌جایی اشیا) | دنبالهٔ حرکت بازو برای رسیدن به تصویر هدف | V-JEPA 2-AC: برنامه‌ریزی zero-shot در محیط جدید با CEM | نمایش‌های واقعی در آزمایشگاه؛ هنوز کند (چند ثانیه برای هر عمل) |
| خودروی خودران / پهپاد | پیش‌بینی آیندهٔ صحنه، ارزیابی مانور قبل از اجرا | world model نهفته برای شبیه‌سازی سناریو و برنامه‌ریزی | پژوهش فعال (مثلاً WA-JEPA)؛ صنعت بیشتر از world model های مولد برای شبیه‌سازی استفاده می‌کند |
| پایش صنعتی و ایمنی | هشدار/توقف خط | surprise = خطای پیش‌بینی (مرحلهٔ ۶) | کاربردی و ارزان؛ با آستانه‌گذاری درست |
| تحلیل ویدیو (ورزش، فروشگاه، مراقبت) | برچسب‌گذاری رخداد، جست‌وجو | embedding ویدیو + probe خطی با دادهٔ برچسب‌دار کم | آماده (V-JEPA 2 باز است) |
| بازی و شبیه‌سازی RL | سیاست عامل | Dreamer / TD-MPC2: یادگیری سیاست درون «رؤیا»ی مدل | تثبیت‌شده در پژوهش |
| مدیریت موجودی/زنجیرهٔ تأمین، انرژی | سفارش، زمان‌بندی | «world model» به معنای مدل پیش‌بینی + MPC (کلاسیک: پیش‌بینی سری زمانی + بهینه‌سازی) | تثبیت‌شده، ولی معمولاً بدون JEPA |
| عامل‌های LLM (مثل همین پروژه) | انتخاب ابزار، پاسخ یا ارجاع به انسان | LLM خودش «world model متنی» است؛ شبیه‌ساز کاربر برای ارزیابی (مرحلهٔ ۶ پروژه) | JEPA مزیت عملی اثبات‌شده ندارد |

**راهنمای انتخاب سریع:**
```
آیا دادهٔ تو پیوسته و پرجزئیات است (تصویر/ویدیو/سنسور)؟
 ├─ نه (متن، جدول، ابزار) ──► LLM + RAG/ابزار، یا مدل‌های کلاسیک. JEPA لازم نیست.
 └─ بله
     ├─ فقط ویژگی برای طبقه‌بندی/جست‌وجو؟ ──► DINOv2/v3، SigLIP، یا V-JEPA 2 (برای ویدیو). probe خطی.
     ├─ باید «اگر این کار را بکنم چه می‌شود» را بدانی؟ ──► world model نهفته (TD-MPC2، DINO-WM، V-JEPA 2-AC) + MPC/CEM
     │      └─ پاداش روشن داری؟ TD-MPC2/Dreamer.  فقط تصویر هدف داری؟ V-JEPA 2-AC / DINO-WM / LeWorldModel.
     └─ هشدار برای رخداد غیرعادی؟ ──► surprise = خطای پیش‌بینی world model + آستانه روی validation
```

**چک‌لیست قبل از ادعای نتیجه** (همان نظم پروژهٔ اصلی):
- [ ] baseline ها: پیکسل خام، encoder تصادفی، یک مدل آماده (DINOv2).
- [ ] چند seed و بازه، نه یک عدد.
- [ ] collapse را با `mean_std` و `effective_rank` چک کردی، نه فقط loss.
- [ ] برای برنامه‌ریزی: planner تصادفی (کف) و oracle (سقف) را هم گزارش کردی.
- [ ] برای surprise: AUC روی دادهٔ جدا + نرخ هشدار کاذب در آستانهٔ انتخابی.
- [ ] زمان اجرا روی سخت‌افزار هدف (تصمیم دیر = تصمیم بد).
